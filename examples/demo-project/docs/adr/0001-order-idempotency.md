# ADR-0001 订单创建的幂等设计

## 背景

客户端在网络超时后可能重复提交同一笔订单。如果不做幂等控制，
用户会被重复扣款，这是典型的资损场景。

## 决策

使用客户端生成的 `requestId` 作为幂等键。
`OrderService#createOrder` 在落库前先按 requestId 查询历史订单，
命中则直接返回首次创建的订单，不再重复下单。

该方案的代价是要求调用方必须生成并传递 requestId，
因此接口文档中把它标记为必填字段。

## 后果

- 重复提交不会产生重复订单；
- 幂等键由 `OrderRequest#requestId` 承载；
- 如果调用方复用同一个 requestId 提交不同金额，会被拒绝（当前实现返回首次订单）。

## 备选方案

使用数据库唯一索引兜底：在订单表上对 `(user_id, request_id)` 建唯一索引。
当前未采用，因为样例工程没有真实的数据库层。
